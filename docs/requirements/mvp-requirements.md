# Comic Explorer MVP要件定義

## 1. 文書情報

| 項目 | 内容 |
| --- | --- |
| 対象 | Comic Explorer MVP |
| 対象ユーザー | Windows PC上に保存した漫画を管理・閲覧する一般ユーザー |
| 対応OS | Windows 10、Windows 11 |
| アプリ形態 | インストーラーで配布するデスクトップアプリ |
| 動作条件 | オフラインで主要機能を利用可能 |
| 要件の根拠 | `docs/requirements/product-questionnaire.md` |
| 文書状態 | Approved。要件オラクル確定済み。性能値は実装後の品質gateで検証する |

## 2. プロダクトゴール

ユーザーが通常のファイルシステム階層をExplorer風の画面で移動し、画像フォルダまたはZIP／CBZの表紙を一覧から見つけ、単ページまたは見開きで漫画を読めることをMVPのゴールとする。

アプリを終了しても読書位置を保持し、再度同じ漫画を開いたときに前回のページから再開できることを必須とする。

## 3. MVPスコープ

### 3.1 対象

- Windows 10およびWindows 11向けデスクトップアプリ
- PC内の1つのライブラリルート
- 通常のフォルダ内にあるJPEG／JPGおよびPNG画像
- JPEG／JPGおよびPNG画像を含むZIP／CBZ
- Explorer風のフォルダツリー、アドレスバー、ナビゲーション操作
- フォルダとZIP／CBZのサムネイル一覧
- 単ページ表示、見開き表示
- 右開き、左開き
- 読書位置のローカル保存
- 読み取り専用の漫画閲覧

### 3.2 MVP対象外

- RAR／CBR、7z、PDF、EPUB
- AVIF、動画、アニメーションGIF
- 縦スクロール、横スクロール、フルスクリーン
- 小サムネイル、詳細リスト、表紙付きリストへの表示切り替え
- お気に入り、タグ、メモ、評価、閲覧履歴
- 外部サービスからの書誌情報取得
- クラウド同期および外部へのデータ送信
- ファイルやフォルダの名前変更、移動、コピー、作成、削除
- 重複作品検出、壊れた書庫検出、自動ファイル監視
- タッチ操作、ゲームパッド操作、ショートカットのカスタマイズ

対象外項目は削除された要求ではなく、MVP後の候補として扱う。

## 3.3 配布ビルド

- GitHubリポジトリの`main`へのpush完了後、GitHub Actions上でWindows向けNSISインストーラーを生成する。
- 生成したインストーラー（`.exe`）は、Actionsの実行結果からArtifactとして取得できる。

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| ライブラリルート | ユーザーが漫画の探索開始位置として登録した1つのローカルフォルダ |
| 漫画フォルダ | 直下または配下に表示可能な画像を含み、1冊として開く対象となるフォルダ |
| 書庫 | MVPではZIPまたはCBZ形式のファイル |
| 漫画項目 | 漫画フォルダまたは書庫の総称 |
| ページ | 漫画項目内の1つの表示可能なJPEG／JPGまたはPNG画像 |
| 表紙 | 漫画項目のサムネイルとして選ばれたページ |
| 自然順 | 数字の連続を数値として比較する、人間の期待に近いファイル名順。例：`2.jpg` は `10.jpg` より前 |
| 次の漫画項目 | 現在の親フォルダ内で、現在選択中の並べ替え順における次の漫画項目 |
| 読書位置 | 漫画項目を一意に識別する情報と、最後に表示したページを特定する情報 |

## 5. 機能要件

## REQ-MVP-001: ライブラリルートの登録

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、漫画を探し始めるフォルダを指定するために、PC内のフォルダをライブラリルートとして登録したい。

**要件:** システムは、ユーザーが選択した読み取り可能なローカルフォルダを1つ、ライブラリルートとして登録できなければならない。登録内容はアプリ再起動後も保持する。

### 受入条件

- REQ-MVP-001-AC1: 初回起動時、ユーザーはフォルダ選択UIから読み取り可能なフォルダを登録できる。
- REQ-MVP-001-AC2: 登録後、選択したパスがフォルダツリーの起点およびアドレスバーに表示される。
- REQ-MVP-001-AC3: アプリを再起動すると、最後に登録したライブラリルートが復元される。
- REQ-MVP-001-AC4: 存在しない、または読み取れないフォルダの場合、アプリは終了せず、対象パスと再選択方法を示す。
- REQ-MVP-001-AC5: 登録済みルートが一時的に消失した場合、同じパスの再試行または別パスの再登録で一覧へ復帰できる。

## REQ-MVP-002: 任意のフォルダ階層

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、既存の保存方法を変更せず漫画を利用するために、任意のフォルダ階層をそのまま閲覧したい。

**要件:** システムは、作者・作品・巻などの固定階層や命名規則を仮定せず、ライブラリルート配下を通常のファイルシステム階層として扱わなければならない。

### 受入条件

- REQ-MVP-002-AC1: サブフォルダ、画像、ZIP／CBZが同じフォルダに混在していても、読み取り可能な対象が表示される。
- REQ-MVP-002-AC2: フォルダ名や階層名から作者、作品、巻のメタデータを自動生成しない。
- REQ-MVP-002-AC3: 深さが異なる複数のフォルダを、階層の深さによる機能差なく移動できる。
- REQ-MVP-002-AC4: folder列挙portは成功、アクセス拒否、対象消失、取消を区別し、
  取消済みgenerationの部分結果を成功として返さない。

## REQ-MVP-003: フォルダツリーによる移動

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、目的のフォルダへ素早く移動するために、左側のツリーでフォルダ階層を操作したい。

**要件:** システムは、ライブラリルート配下のフォルダを左側のツリーに表示し、展開、折りたたみ、選択を可能にしなければならない。

### 受入条件

- REQ-MVP-003-AC1: 展開操作を行うと、選択フォルダ直下のサブフォルダがツリーに表示される。
- REQ-MVP-003-AC2: 折りたたみ操作を行うと、子孫ノードが非表示になる。
- REQ-MVP-003-AC3: ツリー上でフォルダを選択すると、中央一覧とアドレスバーが同じフォルダを表示する。
- REQ-MVP-003-AC4: 読み取りに失敗したフォルダがあっても、他のフォルダの移動を継続できる。

## REQ-MVP-004: アドレスと移動履歴

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、Explorerと同じ感覚で移動するために、現在位置を確認し、戻る、進む、親フォルダへの移動を行いたい。

**要件:** システムは、現在のフォルダパスをアドレスバーに表示し、戻る、進む、上へのナビゲーションを提供しなければならない。

### 受入条件

- REQ-MVP-004-AC1: アドレスバーは中央一覧が表示しているフォルダの絶対パスを表示する。
- REQ-MVP-004-AC2: 有効なフォルダパスを入力すると、そのフォルダへ移動する。
- REQ-MVP-004-AC3: 戻る操作は同一セッション内の直前の表示フォルダへ移動する。
- REQ-MVP-004-AC4: 戻った後の進む操作は、戻る前に表示していたフォルダへ移動する。
- REQ-MVP-004-AC5: 上へ操作はライブラリルートを越えずに親フォルダへ移動する。

## REQ-MVP-005: フォルダ内容の一覧表示

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、読みたい漫画を見つけるために、フォルダと書庫をサムネイル付きの一覧で確認したい。

**要件:** システムは、選択したフォルダ直下のサブフォルダ、漫画フォルダとして開ける対象、およびZIP／CBZを中央のサムネイルグリッドに表示しなければならない。

### 受入条件

- REQ-MVP-005-AC1: 各項目に、種別を識別できるアイコンまたは表紙、表示名を表示する。
- REQ-MVP-005-AC2: 長い表示名はグリッドを崩さず省略し、完全な名前を確認する手段を提供する。
- REQ-MVP-005-AC3: 項目を選択すると、背景色とフォーカス表示によって選択状態を識別できる。
- REQ-MVP-005-AC4: ステータスバーに選択項目の名前と、現在の一覧に含まれる項目数を表示する。
- REQ-MVP-005-AC5: 一覧が表示領域を超える場合、縦スクロールで全項目を確認できる。
- REQ-MVP-005-AC6: 対応画像と子フォルダの両方を持つフォルダでは、Enterまたは
  ダブルクリックをフォルダ移動とし、漫画として開く操作を明示的な「読む」
  コマンドとして別に提供する。

## REQ-MVP-006: 表紙サムネイル

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、内容を視覚的に判別するために、漫画項目の表紙を一覧で確認したい。

**要件:** システムは、漫画フォルダおよびZIP／CBZ内の表示可能ページから表紙サムネイルを生成し、再利用可能なローカルキャッシュへ保存しなければならない。

### 受入条件

- REQ-MVP-006-AC1: 表紙は、隠しファイルを除外した表示可能ページを自然順に並べた先頭ページとする。
- REQ-MVP-006-AC2: 表紙を取得できない項目には、種別を表すプレースホルダーを表示する。
- REQ-MVP-006-AC3: サムネイル生成中も一覧の移動と選択を妨げない。
- REQ-MVP-006-AC4: キャッシュ済みで原本が変更されていない場合、サムネイルを再生成せずキャッシュを使用する。
- REQ-MVP-006-AC5: 原本が変更または削除された場合、古いキャッシュを原本として扱わない。
- REQ-MVP-006-AC6: Windows Imaging ComponentでJPEG／JPG／PNGをdecodeし、EXIF
  orientationを適用した後、アスペクト比を維持して長辺384px以下へ縮小する。長辺が
  384px以下の画像は拡大せず、JPEG quality 82でencodeする。
- REQ-MVP-006-AC7: フォルダとZIP／CBZの表紙生成は同じ自然順先頭ページを使用し、
  書庫entryを原本の隣へ展開しない。
- REQ-MVP-006-AC8: source fingerprintとcache indexでhitとstaleを判定し、cacheは
  app-local領域へatomicに書き込む。失敗は理由と期限を持つnegative cacheへ記録する。
- REQ-MVP-006-AC9: visible、near、backgroundの順で容量制限付きqueueへ投入し、
  worker数、圧縮byte数、decode pixel数を制限する。取消済みまたは古いnavigation
  generationの結果は一覧へ反映しない。
- REQ-MVP-006-AC10: thumbnail cacheは10GiBをhard capとするLRU回収を行い、表示中、
  先読み中、生成中のentryをpinして回収対象から除外する。

## REQ-MVP-007: 一覧の並べ替え

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、多数の項目から目的の漫画を探すために、一覧を条件と方向を指定して並べ替えたい。

**要件:** システムは、中央一覧を名前、更新日時、サイズ、種類で並べ替え、それぞれ昇順と降順を選択できなければならない。

### 受入条件

- REQ-MVP-007-AC1: 名前順は数字部分を数値として比較する自然順を使用する。
- REQ-MVP-007-AC2: 各並べ替え条件で昇順と降順を切り替えられる。
- REQ-MVP-007-AC3: 並べ替え条件を変更しても、表示項目の欠落や重複が発生しない。
- REQ-MVP-007-AC4: 選択中の並べ替え条件と方向を画面上で識別できる。
- REQ-MVP-007-AC5: 数字列の数値が同じ場合は正規化前のUTF-16コード単位の序数順、
  さらに同じ場合は相対パスのUTF-16序数順で決着し、OSの列挙順やロケールへ
  依存しない。
- REQ-MVP-007-AC6: 更新日時またはサイズを取得できない項目は方向にかかわらず
  取得可能な項目の後へ置く。種類の昇順は通常フォルダ、漫画フォルダ、ZIP、CBZ
  とし、主条件が同じ項目は名前自然順、正規化済み絶対パスのUTF-16序数順で
  最終決着する。降順は欠損値を末尾に保ったまま種類順と値順を反転する。
- REQ-MVP-007-AC7: 初回は名前昇順とし、最後に選択した並べ替え条件と方向を
  アプリ再起動後も復元する。
- REQ-MVP-007-AC8: 並べ替えまたはviewer表示設定の保存はnavigation generationと
  独立して管理し、進行中または確定済みの一覧・thumbnail読込みを取消・再投入しない。

## REQ-MVP-008: 画像フォルダのページ読込み

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、既存の画像フォルダを変換せず読むために、JPEG／JPGおよびPNGを漫画ページとして開きたい。

**要件:** システムは、漫画フォルダ内のJPEG／JPGおよびPNGを自然順でページとして読み込まなければならない。

### 受入条件

- REQ-MVP-008-AC1: 拡張子の大文字と小文字を区別せず、JPEG、JPG、PNGを認識する。
- REQ-MVP-008-AC2: 表示可能ページは相対パスとファイル名の自然順で安定して並ぶ。
- REQ-MVP-008-AC3: 対応外ファイルはページとして表示せず、対応画像の閲覧を妨げない。
- REQ-MVP-008-AC4: 読み込めない画像がある場合、そのページをエラー表示またはスキップでき、アプリ全体は終了しない。
- REQ-MVP-008-AC5: Windows上のパス同一性はOSへ委ねる。表示順ではUnicode正規化を
  行わず、自然順で同値となる相対パスを正規化前のUTF-16コード単位の序数順で
  決着する。
- REQ-MVP-008-AC6: page decodeまたはsignature検証に失敗した場合、error contractは
  漫画項目内の対象relative page pathと`データが破損しています`分類を返す。失敗は
  そのpageだけへ局所化し、同じviewer sessionの前後にある正常pageを引き続き読める。

## REQ-MVP-009: ZIP／CBZのページ読込み

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、書庫を手動展開せず読むために、ZIP／CBZ内の画像を直接開きたい。

**要件:** システムは、ZIP／CBZを原本の場所へ展開せず、内部のJPEG／JPGおよびPNGを自然順でページとして読み込まなければならない。

### 受入条件

- REQ-MVP-009-AC1: 拡張子の大文字と小文字を区別せず、ZIPとCBZを認識する。
- REQ-MVP-009-AC2: 書庫内のディレクトリ階層を含む相対パスを使い、ページを自然順で安定して並べる。
- REQ-MVP-009-AC3: 対応外ファイルはページとして表示せず、対応画像の閲覧を妨げない。
- REQ-MVP-009-AC4: 暗号化、破損、または未対応方式の書庫には、対象ファイル名と開けない理由を示す。
- REQ-MVP-009-AC5: 閲覧終了後に原本の隣へ展開済みファイルや管理ファイルを残さない。
- REQ-MVP-009-AC6: archive列挙・page open portは成功、破損、暗号化、未対応、安全拒否、
  取消を区別し、取消済みviewer generationのentryまたはmedia grantを確定しない。

## REQ-MVP-010: 漫画項目を開く

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、一覧から選んだ漫画をすぐ読むために、漫画項目からビューワへ移動したい。

**要件:** システムは、中央一覧で漫画項目を開く操作を受けると、その漫画項目をビューワに表示しなければならない。

### 受入条件

- REQ-MVP-010-AC1: 未読の漫画項目は、最初の表示可能ページから開く。
- REQ-MVP-010-AC2: 読書位置が保存されている漫画項目は、保存されたページから開く。
- REQ-MVP-010-AC3: 表示可能ページがない場合、対象項目と理由を示して一覧へ戻れる。
- REQ-MVP-010-AC4: ビューワを閉じると、開く前に表示していたフォルダと一覧位置へ戻る。
- REQ-MVP-010-AC5: ビューワを閉じると、開く前の並べ替えと選択項目を維持し、
  選択項目を一覧の表示範囲へ戻してkeyboard focusを復元する。

## REQ-MVP-011: 単ページ表示

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、1ページずつ読むために、単ページ表示を利用したい。

**要件:** システムは、1つのページをビューワ領域内へ収めて表示する単ページモードを提供しなければならない。

### 受入条件

- REQ-MVP-011-AC1: ページ全体がビューワ領域に収まる倍率を初期表示に使用する。
- REQ-MVP-011-AC2: アスペクト比を維持し、画像を変形させない。
- REQ-MVP-011-AC3: 前後移動操作により、現在の読み方向に従って1ページずつ移動する。
- REQ-MVP-011-AC4: 先頭または末尾を越える操作で、範囲外のページを表示しない。
- REQ-MVP-011-AC5: 全体フィット時も画像を原寸の100%より拡大せず、
  小さい画像はビューワ領域の中央へ原寸表示する。

## REQ-MVP-012: 見開き表示

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、紙の漫画に近い配置で読むために、2ページを見開き表示したい。

**要件:** システムは、連続する最大2ページを読み方向に従って左右へ配置する見開きモードを提供しなければならない。

### 受入条件

- REQ-MVP-012-AC1: 右開きでは進行方向の先頭ページを右側、次ページを左側へ配置する。
- REQ-MVP-012-AC2: 左開きでは進行方向の先頭ページを左側、次ページを右側へ配置する。
- REQ-MVP-012-AC3: 横長ページは単独の見開き画像とみなし、自動的に1ページだけ表示する。
- REQ-MVP-012-AC4: 末尾に1ページだけ残る場合、そのページだけを表示する。
- REQ-MVP-012-AC5: モードを切り替えても、切り替え前に先頭として表示していたページを失わない。
- REQ-MVP-012-AC6: 初回起動時の表示モードは単ページとし、最後に選択した
  単ページ／見開きモードをアプリ再起動後も復元する。

## REQ-MVP-013: 読み方向

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、作品に適した方向で読むために、右開きと左開きを切り替えたい。

**要件:** システムは、全体設定として右開きまたは左開きを選択できなければならない。

### 受入条件

- REQ-MVP-013-AC1: 設定変更後、ページの配置と前後移動の方向が選択した読み方向に一致する。
- REQ-MVP-013-AC2: 選択した読み方向はアプリ再起動後も保持される。
- REQ-MVP-013-AC3: 初回起動時の既定値は右開きとする。

## REQ-MVP-014: マウスとキーボードによる閲覧

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、好みの入力手段で読むために、マウスとキーボードで主要な閲覧操作を行いたい。

**要件:** システムは、マウスクリック、マウスホイール、およびキーボードで前後ページ移動とビューワ終了を操作できなければならない。

### 受入条件

- REQ-MVP-014-AC1: キーボードだけで前ページ、次ページ、ビューワ終了を実行できる。
- REQ-MVP-014-AC2: マウスクリックだけで前ページと次ページへ移動できる。
- REQ-MVP-014-AC3: マウスホイールで前ページと次ページへ移動できる。
- REQ-MVP-014-AC4: 操作中のキーボードフォーカスを視覚的に識別できる。
- REQ-MVP-014-AC5: MVPでは操作割り当てを固定し、具体的なキーとクリック領域は画面設計で定義する。
- REQ-MVP-014-AC6: ページ読込みはviewer sessionごとのgenerationで管理し、一覧移動の
  navigation generationとは分離する。新しいviewer sessionまたはアプリ終了は旧sessionの
  未開始page requestを破棄し、完了済みの古い結果も画面へ反映しない。
- REQ-MVP-014-AC7: 現在表示するpageと次の表示単位は容量制限付きpage workerで
  読み込み、worker数、queue容量、展開後byte数を制限する。100世代を連続投入した場合も
  最新viewer generationだけが利用可能なmedia grantを確定できる。

## REQ-MVP-015: 読書位置の保存と復元

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、前回の続きから読むために、最後に読んだページを自動保存してほしい。

**要件:** システムは、最後に表示したページをアプリ専用のローカルデータへ保存し、同じ漫画項目を次回開いたときに復元しなければならない。

### 受入条件

- REQ-MVP-015-AC1: ページ移動後、アプリが正常終了しなくても直近の読書位置が失われにくいタイミングで保存する。
- REQ-MVP-015-AC2: アプリ再起動後に同じ漫画項目を開くと、保存されたページを表示する。
- REQ-MVP-015-AC3: 保存ページが削除または変更されて特定できない場合、利用可能な最も近いページを表示し、アプリは終了しない。
- REQ-MVP-015-AC4: 読書位置の保存によって漫画フォルダまたは書庫内に管理ファイルを作成しない。
- REQ-MVP-015-AC5: 保存ページの旧位置から前後の候補が同距離の場合は、読み飛ばしを
  避けるため旧位置以後にある後方候補を優先する。
- REQ-MVP-015-AC6: 読書位置DBが破損または非対応スキーマで開けない場合は、
  アプリ専用領域の`recovery`配下へ元DBを隔離して空DBで継続し、読書位置を
  再初期化したことと隔離先を通知する。ライブラリ原本は変更しない。
- REQ-MVP-015-AC7: viewer終了、次漫画遷移、アプリ終了では最新の確定済み読書位置を
  flushした後にsessionを破棄する。アプリ終了は新規commandとqueue投入を先に拒否し、
  navigation/viewer taskをcancelしてjoinし、archive/file、media token、
  SQLite/WAL/SHMのhandleを閉じてからprocess終了を継続する。

## REQ-MVP-016: 巻末動作

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、連続して読むために、巻末から次の漫画項目へ移動したい。

**要件:** システムは、漫画項目の末尾で次ページ操作を受けると、同じ親フォルダにある次の漫画項目を自動的に開かなければならない。

### 受入条件

- REQ-MVP-016-AC1: 次の漫画項目は、中央一覧で現在選択されている並べ替え条件と方向に基づいて決定する。
- REQ-MVP-016-AC2: 次の漫画項目が存在する場合、確認ダイアログなしでその項目を開く。
- REQ-MVP-016-AC3: 次の漫画項目が存在しない場合、現在の末尾に留まり、巻末であることを示す。
- REQ-MVP-016-AC4: 次の漫画項目に表示可能ページがない場合、その項目を開けないことを示し、現在の漫画または一覧へ戻れる。

## REQ-MVP-017: 原本の非破壊

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、漫画データを安全に保つために、閲覧によって原本を変更してほしくない。

**要件:** システムは、一覧表示、サムネイル生成、画像表示、ページ移動、読書位置保存のすべてにおいて、ライブラリルート配下の原本を変更してはならない。

### 受入条件

- REQ-MVP-017-AC1: 対象操作の前後で画像およびZIP／CBZの内容ハッシュが一致する。
- REQ-MVP-017-AC2: 対象操作の前後で画像、ZIP／CBZ、漫画フォルダの更新日時が変更されない。
- REQ-MVP-017-AC3: キャッシュ、設定、読書位置はライブラリルート外のアプリ専用領域へ保存する。
- REQ-MVP-017-AC4: 書庫は読み取り専用で開き、書庫内へファイルを追加、更新、削除しない。
- REQ-MVP-017-AC5: 漫画画像を返すcustom protocolは、Tauriのplatform mappingに従い
  Windowsでは`http://comic.localhost/<token>`、その他の対応platformでは
  `comic://localhost/<token>`という固定scheme/authorityを使用する。queryとfragmentを
  持たない単一token path、許可済みOrigin/Referer、GET methodだけを
  受け付ける。重複または不正byteのsecurity header、traversal、絶対/drive/UNC path、
  任意の書庫entry名を拒否し、成功・失敗の全応答へ正確なContent-Type/Length、
  `nosniff`、限定CORSを付け、原本pathや内部errorを応答へ含めない。

## REQ-MVP-018: ローカル完結と外部送信禁止

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、プライバシーを守るために、漫画や利用情報を外部へ送信せず利用したい。

**要件:** システムは、MVPの実行中に漫画データ、ファイル名、フォルダ名、読書位置、利用状況を外部へ送信してはならない。

### 受入条件

- REQ-MVP-018-AC1: ネットワークへ接続できない環境でも、MVPの全機能を利用できる。
- REQ-MVP-018-AC2: 自動テレメトリ、クラッシュレポート、書誌情報取得、クラウド同期を含まない。
- REQ-MVP-018-AC3: 外部通信を行う依存ライブラリを使用する場合、その機能を無効化し、検証方法を設計文書に記録する。

## REQ-MVP-019: エラーからの継続

**優先度:** Must

**ユーザーストーリー:** ユーザーとして、一部のファイルに問題があっても、他の漫画の閲覧を続けたい。

**要件:** システムは、アクセス拒否、消失ファイル、破損画像、破損書庫など項目単位のエラーによってアプリ全体を終了してはならない。

### 受入条件

- REQ-MVP-019-AC1: エラー表示には対象パスと、ユーザーが次に実行可能な操作を含める。
- REQ-MVP-019-AC2: エラー発生後もフォルダ移動、一覧への復帰、別項目の閲覧を行える。
- REQ-MVP-019-AC3: エラー表示によって原本の削除、修復、上書きを自動実行しない。
- REQ-MVP-019-AC4: 利用者向けエラー分類は`アクセスできません`、
  `見つかりません`、`対応していません`、`データが破損しています`、
  `暗号化されています`、`一時的に使用できません`、`アプリデータを再初期化しました`
  とする。内部例外やstack traceを主メッセージへ表示せず、対象、簡潔な理由、
  安全な回復操作を示す。
- REQ-MVP-019-AC5: UI-backend境界の全responseは要求時のrequest IDとgenerationを
  保持し、success、分類付きerror、cancelを構造的に区別する。取消済みまたは古い
  generationの実port結果はsuccessとしてUIへ返さない。

## 6. 非機能要件

## NFR-MVP-001: 対応規模

**優先度:** Must

**要件:** システムは、ライブラリ全体1TB、10,000ファイル、1,000作品、1冊300ページを想定した設計としなければならない。

### 受入条件

- NFR-MVP-001-AC1: 10,000項目の存在を理由に、全項目のサムネイルをメモリへ同時保持しない。
- NFR-MVP-001-AC2: 一覧外の項目を必要に応じて遅延処理できる構造とする。
- NFR-MVP-001-AC3: 基準データによる性能試験で、メモリ使用量、処理時間、キャッシュ容量を記録する。
- NFR-MVP-001-AC4: サムネイルfile cacheは10GiBを既定hard capとし、LRUで
  超過分を回収する。現在表示中または生成中のentryは処理中に削除しない。

## NFR-MVP-002: 性能目標

**優先度:** Should

**要件:** システムは、`docs/testing/performance-benchmark-plan.md`で確定した
基準Windows PC、データセット、測定条件上で、次の性能目標を満たさなければならない。

### 受入条件

- NFR-MVP-002-AC1: 通常のコールド起動から操作可能になるまで3秒以内である。
- NFR-MVP-002-AC2: キャッシュ済みフォルダの一覧を1秒以内に表示する。
- NFR-MVP-002-AC3: 先読み済みページは入力から100ミリ秒以内に切り替わる。
- NFR-MVP-002-AC4: 10,000項目を対象とする名前検索結果を1秒以内に表示する。
- NFR-MVP-002-AC5: 基準PC、ストレージ種別、書庫サイズ、画像解像度を性能設計で固定し、測定結果を再現可能にする。
- NFR-MVP-002-AC6: idle working setは250MiB以下とし、50msを超えるUI long taskを
  記録してnavigation中のp95を100ms以下にする。

検索UIはMVP対象外であるため、NFR-MVP-002-AC4は検索機能を実装するリリースまで保留する。

## NFR-MVP-003: キーボードアクセシビリティ

**優先度:** Must

**要件:** システムは、主要な移動と閲覧操作をキーボードだけで実行でき、現在の選択位置およびフォーカス位置を視覚的に識別可能にしなければならない。

### 受入条件

- NFR-MVP-003-AC1: フォルダツリー、中央一覧、ビューワの主要操作へキーボードで到達できる。
- NFR-MVP-003-AC2: フォーカスを持つ操作対象が常に視覚的に識別できる。
- NFR-MVP-003-AC3: キーボード操作とマウス操作で同じ項目を選択した場合、結果が一致する。
- NFR-MVP-003-AC4: `ヘルプ`からネットワーク不要のアプリ内キー操作ダイアログを
  開け、Escまたは閉じる操作で元のフォーカス位置へ戻れる。

## NFR-MVP-004: 無料で再配布可能な依存関係

**優先度:** Must

**要件:** システムは、有料ライセンスを必要とする依存関係を使用してはならず、一般ユーザー向けインストーラーとして再配布可能なライセンスだけを採用しなければならない。

### 受入条件

- NFR-MVP-004-AC1: 使用する直接依存関係の名称、バージョン、ライセンス、配布条件を一覧化する。
- NFR-MVP-004-AC2: ライセンス表示またはソース提供義務がある場合、配布物に必要な文書を含める。
- NFR-MVP-004-AC3: 有料ライセンス、用途制限、一般配布を禁止するライセンスを含まない。
- NFR-MVP-004-AC4: npmおよびCargoのlockfileに含まれる直接・推移依存を
  機械的に監査し、SPDXで判定できないlicenseまたは禁止licenseを0件とする。
  SBOMと`THIRD-PARTY-NOTICES.md`は同じlockfile inventoryから生成・検証する。

## NFR-MVP-005: Windows配布

**優先度:** Must

**要件:** システムは、Windows 10およびWindows 11で利用可能なインストーラーを生成できなければならない。

### 受入条件

- NFR-MVP-005-AC1: サポート対象のWindows 10環境でインストール、起動、アンインストールを確認できる。
- NFR-MVP-005-AC2: サポート対象のWindows 11環境でインストール、起動、アンインストールを確認できる。
- NFR-MVP-005-AC3: アンインストール時にライブラリルート配下の原本を削除または変更しない。
- NFR-MVP-005-AC4: Windows 10の互換性基準は22H2 x64、Windows 11はサポート中の
  x64ビルドとする。
- NFR-MVP-005-AC5: アンインストールは既定で
  `%LOCALAPPDATA%\ComicExplorer`の設定、読書位置、キャッシュを残す。
  明示的な削除チェックボックスを選んだ場合だけアプリ専用領域を削除し、
  ライブラリルートは常に対象外とする。

## NFR-MVP-006: UXを優先した技術構成の検証

**優先度:** Must

**要件:** システムのアプリケーション基盤、UI、ローカルDB、ZIP／CBZ処理、画像処理、キャッシュ、テストおよび配布方式は、一次情報による比較と再現可能な性能スパイクに基づいて選定しなければならない。

### 受入条件

- NFR-MVP-006-AC1: 操作応答性、ページ切り替え、一覧・スクロール、メモリ、起動、エラー時UX、統合、Windows操作性、テスト容易性、ライセンス・配布を重み付きで比較する。
- NFR-MVP-006-AC2: 実測値、推定値、未測定値を明確に区別する。採用決定後も
  Windows実機の未測定項目を品質リスクとして残し、性能gateで継続検証する。
- NFR-MVP-006-AC3: 1,000／10,000項目、300ページ、ZIP／CBZ、破損データ、未生成／生成済みキャッシュを含む著作権上問題のない生成データと測定手順を用意する。
- NFR-MVP-006-AC4: 最初に操作可能になるまでの時間、入力遅延、p95、UIスレッドの長時間停止を総処理時間と分けて評価する。
- NFR-MVP-006-AC5: 採用構成ごとに理由、UX・性能上の利点、欠点、ライセンス、却下候補および再評価条件を記録する。
- NFR-MVP-006-AC6: malformed ZIP/image/security corpusは固定seedのfixture
  generatorからWindows、WSLおよび通常のLinux CIで再現でき、既存出力は明示的な
  置換指定なしに上書きしない。platform固有のpath変換は、そのplatformで利用可能な
  interfaceを検出した場合だけ実行する。
- NFR-MVP-006-AC7: release前に実装済みの全library read経路をbefore/after
  snapshotで囲み、相対path、種別、size、mtime、内容hash、ZIP entry一覧が一致し、
  library配下にDB、cache、temp、logまたはsidecarが新規作成されないことを自動検証する。

## 7. UIの外観に関する制約

会話に添付された「Leeyes - comic」の画像を、情報配置と操作密度の参考とする。完全な複製は要求しない。

MVPのメイン画面は、上からメニューバーまたは主要操作領域、ツールバー、アドレスバーを配置し、その下を左側のフォルダツリーと中央のサムネイルグリッドへ分割する。下部には選択情報と項目数を示すステータスバーを配置する。

メインウィンドウの最小client sizeは1024×720 CSS pxとする。フォルダツリーは
初期幅240px、最小幅180px、中央一覧は残り幅を使用する。サムネイルcellは
176×248pxを基準とし、100%〜200% DPIではCSS pxを維持してOS scalingへ従う。

UIは次の状態を視覚的に区別できなければならない。

- 通常項目
- 選択項目
- キーボードフォーカス
- サムネイル生成中
- 読み込み失敗
- 操作不能なナビゲーション

## 8. 要件間の整合規則

- フォルダツリー、アドレスバー、中央一覧は常に同じ現在フォルダを指す。
- 中央一覧の選択項目とステータスバーの選択情報は一致する。
- 読み方向は、見開きの左右配置、前後移動、マウス操作、キーボード操作へ一貫して適用する。
- 読書位置はページ番号だけに依存せず、原本の軽微な変更後にも可能な範囲で同じページを特定できる設計とする。
- エラー回復のために原本を自動変更しない。
- キャッシュとローカルDBは削除しても原本から再構築可能でなければならない。ただし、読書位置など原本に存在しない利用者データはバックアップ対象として設計する。

## 9. 全体受入シナリオ

### E2E-MVP-001: 画像フォルダを見つけて読む

1. ユーザーがライブラリルートを登録する。
2. ユーザーがフォルダツリーで目的のフォルダへ移動する。
3. システムが漫画フォルダとZIP／CBZをサムネイル一覧へ表示する。
4. ユーザーが画像フォルダを開く。
5. システムがJPEG／PNGを自然順で単ページ表示する。
6. ユーザーが見開きへ切り替え、右開きでページを移動する。
7. ユーザーがビューワとアプリを終了する。
8. ユーザーがアプリを再起動して同じ漫画を開く。
9. システムが前回最後に表示したページを復元する。

### E2E-MVP-002: ZIP／CBZを原本変更なしで読む

1. テストが対象ZIP／CBZと親フォルダの属性および内容ハッシュを記録する。
2. ユーザーがZIP／CBZを一覧から開く。
3. システムが書庫を原本の場所へ展開せずページを表示する。
4. ユーザーが複数ページを移動し、サムネイルキャッシュと読書位置を生成する。
5. テストが操作前後の原本の属性および内容ハッシュが一致することを確認する。

### E2E-MVP-003: 巻末から次の漫画へ進む

1. 同じフォルダに複数の漫画項目を配置する。
2. ユーザーが名前の自然順・昇順を選択する。
3. ユーザーが漫画項目の末尾で次ページ操作を行う。
4. システムが一覧の次の漫画項目を開き、その先頭または保存済みページを表示する。
